# analytics.instructors_info

**Status:** Live (80 rows). **Not the same as `analytics.Instructor`** — this looks like a manually-maintained internal ops roster (KAM assignment, document expiry tracking, security deposit status), not the app's own instructor account table.

**Purpose:** An operational spreadsheet-style record per instructor — KAM assignment, vehicle/document compliance (DL/FC/PUC/Insurance expiry dates via the `checklist` jsonb field), availability notes, and security deposit status. Free-text-heavy, clearly filled in by hand rather than generated by the app.

**Grain:** One row per instructor.

## Relationships

`kam` is free text, not a FK to the `KAM` table. No enforced relationships anywhere on this table.

## Gotchas

- **Almost entirely free text**, including fields that look like they should be structured (booleans, dates, numbers) — treat as a human-maintained reference sheet, not a system of record.
- `checklist` dates are `DD/MM/YYYY` strings inside JSON — don't assume ISO format.
- `status = 'Yes'/'No'` meaning is unconfirmed — don't assume it means "active."
- Likely duplicates identity information already in `Instructor`/`instructor_availability` but isn't linked to either by a real key — cross-referencing requires matching on `mobile_number`/name, not an ID join.
