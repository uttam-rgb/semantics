25. ~~**The call-to-lead phone-number join isn't 100%**~~ — **RESOLVED (method), still open (handling)**: adjudicated 2026-09-12 against `Lane_Metric_Definitions_v1.xlsx` — switched from `ltrim(number,'0')` to last-10-digits (the spreadsheet's documented standard, and empirically found slightly more matches). ## Adjudicated against Lane_Metric_Definitions_v1.xlsx (2026-09-12)
Full conflict-by-conflict review of this spreadsheet (the Analytics team's own semantic spec, copied into [`reference/Lane_Metric_Definitions_v1.xlsx`](reference/Lane_Metric_Definitions_v1.xlsx) for permanence) against production SQL. Resolved: revenue source table (cratio_leads_analytics confirmed, not daily_report_snapshots), conversions/sales count source (live CRM count confirmed), converted-stage set (added `DP PAID`), call direction filter (`!= 'inbound'` confirmed, `outbound-api` stays included), call source table (`exotel_calls` confirmed over self-reported `daily_report_snapshots.total_calls_made`), phone normalization (switched to last-10-digits), and full-payment=`CLOSED WON` (confirmed). Still open from that review:
32. **`DP PAID`'s sub-bucket is unassigned** — it's part of "Total Conversions" but not part of either "Full-Payment" or "Partial-Payment" conversions (that breakdown query only checks `CLOSED WON`/`50% PAYMENT DONE`). Only 9 rows — low stakes, but the two sub-buckets won't sum to the total until this is decided. See [metrics/conversion_rate.md](metrics/conversion_rate.md).
33. **The spreadsheet's "Sales Team Only" roster restriction** (build the sales team from `daily_report_snapshots`' distinct `lead_owner`s, exclude shared/admin/founder accounts) **isn't applied in `call_activity.md`** — that doc attributes calls to whatever `lead_owner` the phone match returns, with no roster filter. Add if agent-level call totals need to match the spreadsheet's documented methodology exactly.
34. **Two different `lead_stage` groupings exist in the spreadsheet for different purposes** — "Lead Rules" (Live/Hot/Dead/Cold/Converted/Lost/Future Prospect, used for this project's `conversion_rate.md`) vs. "Business Rules → Status Bucket" (Won/Hot/Dead/NonServiceable/Live, for a not-yet-built Source Wise Summary / Agent Lead Status metric family). They disagree on where `50% PAYMENT DONE` lands (Converted vs. default-bucketed as Live). Keep them separate when building the Live/Hot/Dead-Leads metrics from `future_work.md` — don't assume `conversion_rate.md`'s mapping applies there too.
